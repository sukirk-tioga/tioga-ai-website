02 — What we do each day

  • Day 1 — Discovery. Shadow the current AP exception process, interview the buyer/AP team, pull a sample of real exception volume and type from the last 90 days.
  • Day 2 — Scope the write path. Identify the one sanctioned application-logic write path (not a database shortcut) an agent would execute through, and the approval/escalation policy that already governs it today.
  • Day 3 — Build a working prototype. A governed agent that reads an exception, proposes a resolution, and routes it through policy — against a scoped, synthetic dataset shaped like the real one.
  • Day 4 — Governance mapping. Map every decision point in the prototype to NIST AI RMF (or your applicable framework) so the evidence trail is audit-legible from day one, not bolted on after.
  • Day 5 — Readout. Live walkthrough of the working prototype, a written ROI estimate (hours reclaimed, error-rate impact), and a production build plan with price and timeline.

03 — What you leave with

1A working prototype against your actual workflow shape, not a slideware demo
2An ROI estimate with the assumptions shown, not just a headline number
3A production build plan — price, timeline, and what's explicitly out of scope
4A governance-mapping worksheet for the one write path assessed

04 — What this sprint does not include

  • Production deployment or a live connection to your real systems
  • A multi-workflow rollout plan (scoped to the one workflow assessed)
  • Security/compliance sign-off — that's a deliverable of the production build, not the sprint
